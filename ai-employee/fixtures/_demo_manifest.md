# Demo-fixture manifest

`[SYNTHETIC FIXTURE MANIFEST]`

This manifest documents which fixtures are loaded by
`ai-employee/bin/load-demo-fixtures.sh` and the row shapes they
translate into when seeded into a customer's substrate. It is the
contract between the corpus (PR #832 and the generator output) and the
loader (issue #890).

The loader never modifies any file under `ai-employee/fixtures/`. The
corpus is read-only at runtime. This manifest exists in
`ai-employee/fixtures/` for proximity to what it documents; the loader
itself lives in `ai-employee/bin/`.

## Tagging

Every row the loader writes carries:

```json
"metadata": {
  "is_demo_fixture": true,
  "watermark": "[SYNTHETIC FIXTURE — NOT A REAL MATTER]",
  ...
}
```

The `is_demo_fixture: true` field is the load / unload key. The
`watermark` field is the dashboard-visible label. The two are written
in lockstep; the loader does not write one without the other.

## Removal contract

Calling `load-demo-fixtures.sh <slug> <vertical> --unload` removes every
row tagged `is_demo_fixture: true` from the per-customer memory and
voice stores. Re-runs after removal are no-ops. The unload path
enforces the same "no non-demo rows in the substrate" guard as the load
path: if a foreign row is present, the tool refuses with exit 4 and
removes nothing. This is intentional: a demo loader must not be the
last code path that touched a real customer's data.

## Future verticals

Future verticals register a `VerticalConfig` in
`bin/lib/demo_fixtures.VERTICAL_REGISTRY` and add a corpus directory
under `ai-employee/fixtures/<industry>/<vertical>/`. The matters parser
is currently PI-specific; other verticals supply their own envelope
parser. This manifest is updated in lockstep.
